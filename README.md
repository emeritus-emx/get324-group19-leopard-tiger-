# GET 324 Group 19: Leopard versus Tiger Classifier

This repository contains the Group 19 mini project for GET 324 Laboratory
Exercise 10. It trains a convolutional image classifier in Google Colab and
deploys the saved model as a Streamlit web application.

## Project objective

The application accepts one wildlife image and classifies it as either:

- `leopard` (class 0)
- `tiger` (class 1)

It also displays the model confidence and both class probabilities.

## Why transfer learning is used

The project uses MobileNetV3Small with weights learned from ImageNet. The
convolutional base already recognises general visual patterns such as edges,
textures and shapes. Training a small new classification head is faster and
usually more reliable for a limited student dataset than training a large CNN
from random weights. The upper layers are later fine-tuned with a low learning
rate.

## Dataset

The notebook uses the
[Big Cats Image Classification Dataset](https://www.kaggle.com/datasets/patriciabrezeanu/big-cats-image-classification-dataset)
on Kaggle. The source contains several big-cat classes; the notebook retains
only the leopard and tiger folders. It verifies the images, rejects duplicate
files, and creates stratified training, validation and test sets.

The project code does not redistribute the source dataset. The notebook
downloads it directly from Kaggle.

## Procedure 1: Train the model in Google Colab

1. Open [Google Colab](https://colab.research.google.com/).
2. Select **File > Upload notebook**.
3. Upload `Group19_Leopard_vs_Tiger_Colab.ipynb`.
4. Select **Runtime > Change runtime type > T4 GPU > Save**.
5. Run the notebook cells from top to bottom.
6. If Kaggle asks for authentication, create an API token from your Kaggle
   account settings and follow the notebook prompt.
7. Inspect the sample images and class counts before training.
8. Record the test accuracy, precision, recall, F1 score and confusion matrix.
9. Download these two deployment files when training finishes:
   - `leopard_tiger_model.keras`
   - `model_info.json`
10. Replace the placeholder `model_info.json` in this folder with the one
    generated by Colab.
11. Put `leopard_tiger_model.keras` beside `app.py`.

### What each data split does

- The training set updates model weights.
- The validation set controls early stopping and threshold selection.
- The test set remains untouched until final evaluation.

Using the test set during training would give an unrealistically optimistic
performance estimate.

## Procedure 4: Deploy with Streamlit Community Cloud

1. Go to [share.streamlit.io](https://share.streamlit.io/).
2. Sign in and connect the GitHub account.
3. Select **Create app**.
4. Choose the `get324-group19-leopard-tiger` repository.
5. Select the `main` branch.
6. Set the entrypoint file to `app.py`.
7. Choose Python 3.11 when the deployment settings provide a Python-version
   option.
8. Select **Deploy**.
9. Watch the deployment logs. The first installation can take several minutes
   because TensorFlow is large.
10. Open the generated `streamlit.app` URL and test both animal classes.
11. Copy the public URL into the submission report.

Streamlit Community Cloud installs the Python packages listed in
`requirements.txt` and reruns the application whenever the GitHub repository is
updated.

## How the application makes a prediction

1. Streamlit receives an uploaded image.
2. Pillow converts it to RGB and resizes it to 224 by 224 pixels.
3. The image is converted to a floating-point NumPy batch.
4. The Keras model returns the probability of the positive class, tiger.
5. The threshold stored in `model_info.json` converts the probability into a
   tiger or leopard label.
6. The application displays the selected label and confidence.

## Common problems

### The app reports that the model is missing

Run the Colab notebook and put `leopard_tiger_model.keras` beside `app.py`.

### Kaggle refuses the download

Create a Kaggle API token and use the login prompt in the notebook. Do not
publish the token in GitHub.

### Streamlit deployment cannot install TensorFlow

Confirm that the app uses Python 3.11 and that `requirements.txt` is at the
repository root. Review the deployment log for the exact failed dependency.

### The prediction labels are reversed

The model uses `0 = leopard` and `1 = tiger`. Do not change the order in
`model_info.json`.

### GitHub rejects the model file

GitHub blocks individual files larger than 100 MB. MobileNetV3Small should
normally stay below that limit. If a later model exceeds it, use Git LFS or
export a smaller inference model.
